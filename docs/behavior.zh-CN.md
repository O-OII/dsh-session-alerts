# 逐会话计数与精确已读确认

[README](../README.zh-CN.md) · [English](behavior.md)

## 唯一的确认策略

统计有未读有效结果或未解决输入请求的主会话并集，每个会话一次。过滤子代理 origin/delegation。显示 `1`～`99`，再显示 `99+`，逻辑数字上限 999。完成、出错、阻塞、输出超限均可计入，不取决于哪个窗口或应用位于前台。

示例：A、B、C、D、E 完成，计数 **5**。切回 DSH 但 A 仍停在旧内容：**5**。将 A 最新结果的页脚滚入视口：**4**，B～E 仍未读。B 又出新结果，只更新 B 的未读版本，不重复加会话数；查看 B 旧轮次不能确认新结果。

没有 OS 焦点推断、窗口清零模式、兼容回退、DOM 标题发现、通用打开会话监听或客户端“一键清全部”操作。

## 官方客户端 → Host 链路

1. 包内客户端贡献在官方 `conversation.chat.turnTail` 列表 Slot 注册一像素测量标记。只有 Chat 将真实 `turn/end` 实体化后才出现该页脚；不替换 Chat 渲染器、不改应用源码。
2. 标准 Hook 从 `uiConversation.binding(binding).target('chat').timeline` 读取真实 `turn/end.seq`。Slot 自身的 `seq` 可能是更早的 assistant 消息序号，**不能当作轮末证据**。
3. 官方 `uiSession.current` 必须指向该主会话，文档可见且有焦点，IntersectionObserver 证明页脚进入视口；发送前再校验本标记的几何尺寸与可见性。仅打开/保留 Session 不算已读；卸载、不活动或隐藏的结果不能确认。
4. 经带官方认证与生命周期管理的 `connection.rpc`，只获取此会话的未读版本，核对 kind/轮次/末序号，再提交 `{ sessionId, revision, kind, turn, eventSeq }`。
5. Host 校验 owner 权限、请求形状、取消状态、挂载存活、随机挂载 epoch 和当前精确版本，同步 CAS 仅确认此结果。客户端不乐观减数。

每次新提醒都有挂载内唯一版本，随机 epoch 拒绝上一 Host 的确认。结果更新与确认同步处理：先 ACK 后新结果，新结果仍未读；先新结果后旧 ACK，拒绝旧确认。两个窗口重复确认同一结果只减一次。失去/恢复可见性会中止在途证据，重连重新取证；Host 不保存会自动读取未来结果的粘性“活动窗口租约”。

## 等待、取消与生命周期

- `notifyOnWaiting` 启用时，审批/问题保留计数，直到实际决定/回答或所属操作结束。**目前不支持仅查看临时输入界面即确认**；SDK 没有等价的精确“问题已渲染”页脚接口，不能拿活动会话标题或打开事件猜测。
- 同一会话的终态未读与临时等待分别保留。新轮次/等待及其解决不会丢掉旧未读结果；查看旧结果也不会替用户解决当前请求。
- 新有效终态结果替换旧结果，并结束本轮临时等待。取消不新增提醒，只结束等待，保留旧未读；历史恢复 `interrupted`/`forked` 不通知。
- 默认不通知活动目标成功的中间轮次；目标最终完成和有效失败仍可计入。通知偏好不是已读模式开关。
- Host Session-store detach 是对象卸载，不是已读/删除证据：保留终态未读与轮次去重，结束临时等待，拒绝晚到事件，直到有效新轮次开始。
- 页面刷新、断线、helper 重启保留 Host 内存状态。**Host 重启、插件重载/停用或崩溃不持久化未读**，不从历史日志补发。删除或无法再查看的旧会话可能保留待查看计数直至重置插件；不会把对象卸载冒充持久删除 API。

## 原生显示与限制

helper 只绘制 Host 聚合数字，前台也保留，不读取 OS 前台焦点。完整 exe 路径匹配的所有可见窗口显示同一数字；清理重验记录的句柄，拓扑变化和绘制错误重试当前目标值。不匹配标题、不改应用身份。同一 exe 的多个独立 Host 实例无法区分，不应为它们启用相互竞争的角标提供者；不恢复仅托盘隐藏窗口。

自动已读仅覆盖 **Chat 结果页脚**；其他视图、客户端贡献/IntersectionObserver 不可用、或没有滚到页脚时，保守保留未读。“查看”仅表示上述浏览器暴露条件，不是眼动追踪或理解证明；文档可见性未反映的 OS 遮挡无法确认。fake 测试证明状态/桥接顺序，不代表真实浏览器布局、shell/DPI 或所有 Explorer 行为验收。资产图不会冒充原生截图。
